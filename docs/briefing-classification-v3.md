# 帝国简报 V3 — 议会政务与 Daily News 的分类契约

> 用户验收：议长投票及其他进行中的议会事项必须出现在「我的政务」，不能仅作为 Daily News 的消息。
> 保留已确认的 V2.6 视觉（奶白背景、八色细线、淡填色椭圆、原始平面天命标志）。

## 1. 单一真实来源

**正在进行、成员可以参与或必须处理的议会事项 → 我的政务。**

**正式结束的公开结果、既有国家纪事、随代码上线的功能公告 → Daily News。**

议会审计日志不是任务本身，不能按时间把 `submitted`、`speaker_election_opened`、
`speaker_vote_cast`、`debate_opened`、进入投票阶段的 `stage_transition` 直接塞进 Daily News。

### 我的政务（按真实状态实时计算）

| 事件 | 判定源 | 谁看到 | 状态与完成条件 |
| --- | --- | --- | --- |
| 提案征询 | `parliament_items.stage = proposal` | 可访问议会的已登录成员 | 可参与；离开提案阶段后不再显示 |
| 议长选举开放 | `parliament_meeting_sessions.speaker_status = open`，截止尚未到 | 所有已登录成员 | 可报名；本人已登记时显示已登记；选举截止、关闭后移除 |
| 议长选举投票 | 选举仍开放、存在候选人、`parliament_speaker_votes` 中本人尚未投票 | 尚未投票成员 | 待投票；本人投票后立即从待办计算结果中移除 |
| 正式辩论开始 | 议案处于 debate/amendment 且 `debate_started_at` 非空 | 可访问议场的成员 | 可参与；离开辩论阶段后移除 |
| 议案正式表决 | 议案处于 voting，版本有效，`parliament_votes` 中本人无该版本选票 | 尚未投票成员 | 待投票；投票完成后移除 |
| 公投开始 | 议案类型为 referendum，且真实 voting 阶段正在进行 | 有权在现有议会系统投票的成员 | 待投票；投票完成后移除。*当前后台尚不能创建新的 referendum 类型，待未来议会业务实现* |

不同事项用稳定 `task.id` 去重；按可计算日期升序，日期相同时早创建者优先，无日期放最后。
全屏简报仅展示最紧迫三项；简报台完整显示。点击跳转到对应议案的提案讨论、议长选举、议场或表决区域，而不是只打开议会首页。

## 2. DDL 与倒计时必须严格对应真实字段

| 事项 | 现有服务端字段 | UI 标签 |
| --- | --- | --- |
| 议长选举报名/投票 | `parliament_meeting_sessions.speaker_election_deadline`，服务端强制校验 | **DDL：明确日期/时间，剩余：实时倒计时** |
| 新提案、普通表决、公投、辩论 | `parliament_items.deadline` 仅为议案预期日期；服务端未实施对应硬截止 | **预期日期：明确日期，距预期：实时倒计时**，不得写成正式投票截止 |
| 任何未设置日期的开放事项 | 当前无有效的截止字段 | **DDL：尚未设置，剩余：—** |

倒计时只在前端每秒更新；仅服务器判断操作是否仍然开放。
`YYYY-MM-DD` 日期视为新加坡时区该日末（23:59:59.999 UTC+08:00），带时区的日期按其绝对时间计算。
一旦硬截止已过，议长选举即使未因惰性结算改写 D1，也不得向成员继续提供“可投票”待办。

**尚未满足的要求：** 若希望提案、辩论、普通表决、公投都必须有真正的强制 DDL，需要在议会业务层增加**各阶段独立截止字段、设置 UI 和服务端执行规则**。这属于业务规则变更，不应把既有预期日期默默重解释成强制截止，也不应在 PR #5 中和 PR #4 的迁移编号冲突。

## 3. Daily News 规则

- 保留已有国家纪事与成功发布到网站版本的功能新闻。
- 仅允许能够从审计事件验证的正式结束事项进入议会相关新闻：`speaker_elected`、`speaker_tie_resolved`、`speaker_appointed`、从 `stage_transition` 且 `metadata.to = resolved` 明确结案的事件。
- 严禁把候选登记、本人投票、议场发言、实时辩论、投票开放包装为“已通过 / 已生效”新闻。
- 全部新闻按发布时间倒序保留；登录简报 4 条后可展开全部，简报台显示全部；不虚构事件。

## 4. 个人权限与数据隔离

- `/api/briefing` 只接受服务器验证的 `currentMember(request)`，不读取客户端自报的 memberId。
- 议长候选人和选票基于当前用户过滤；一个成员投票不影响其他成员的待投状态。
- 公民身份、权限、审核和选票的写入仍由原有 `/api/parliament` 执行；简报是**只读视图**。
- 未上线的 Messenger 与在线成员来源不冒充真实状态。

## 5. 验收测试

1. 同一议案开放议长选举，当前账户未投票：简报里必须同时识别开放选举和待投票；Daily News 没有实时投票记录。
2. 当前成员投出议长选票，重新同步后待投票消失；另一成员未投时仍显示。
3. 议长选举到期、撤销或关闭后任务消失，不显示虚假的剩余时间。
4. 当选议长明确宣布开会后，辩论进行中事项进入政务；只进入 debate 阶段但尚未开会时不得错误称“辩论已开始”。
5. 无日期显示“尚未设置 / —”，预期日期明确非硬截止；真正议长选举 DDL 有秒级倒计时。
6. 点击三类事项分别直达具体提案、议长候选/投票区和辩论区；不改现有法案及游戏存档。
7. 网站仅在独立预览 Worker 上部署本功能，不合并至生产 main。
