# 帝国简报 V2：AI 开发新闻规则（无人工发布后台）

## 发布流程

你让 AI 编程助手实现、测试并部署一个新功能时，若确有值得全体成员知道的变化，编程助手应同时更新 `app/briefing/feature-news.ts`，追加一条结构化新闻。**不要**要求站长再到网站上填写新闻发布表单。

这条新闻与功能代码同属一个网站版本：只有相应版本成功部署后，成员才能从 `/api/briefing` 看到这条新内容；开发分支和失败的部署不应成为线上新闻。

## 写入格式

```ts
{
  id: "release:<unique-feature-and-version>",
  title: "准确、简短的中文标题",
  summary: "仅描述已开发并准备上线的功能；不编造效果和进度",
  category: "新功能", // 或 游戏、Lounge、网站更新
  publishedAt: "明确的实际版本发布时间（带 +08:00 时区）",
  target: "club", // 已有可访问导航目标
  targetId: undefined, // 若未来实现具体功能链接，填对应稳定 ID
}
```

不得使用未来时间伪造发行时间；日期不确定时应在实际发布时由部署工序生成真实发布时间。现阶段可使用实际准备发布的时间，但不得宣称在部署前已经向公民发出新闻。

## 约束

- 不自动宣布尚未通过的法律已经生效，也不把提案视为正式法律。
- 不发布纯代码重构、修复测试、私人资料、秘密消息或成员的个别待办。
- 同一功能同一版本只记录一次；更新 `id` 必须稳定并可去重。
- 所有历史新闻留存，不因 Daily News 首页折叠而丢弃。
- 新闻默认为纯文字和分类图标，**不需要人工绘制图片**。
- 成员相关的标志与配色来自独立的视觉资产配置，不嵌入新闻背景。
- 若未来接入 Workers AI，AI 只能根据已验证的更新事件生成标题和摘要；自动调用 AI 不是正常浏览新闻的前提。

## 当前覆盖范围

- 已支持：固定历史新闻、来自议会审计的提交与阶段变更、由开发 AI 随发布代码写入的功能新闻。
- 未支持：部署系统自动判定变更是否值得发布、Workers AI 在线润色、复杂公告收件回执、完整 Messenger、重大特刊生成和馆藏。
- 因为没有配置持续部署成功回调，发布者仍需核实 Cloudflare 实际部署状态。即使提前写入该文件，只要新代码没有部署上线，线上不会出现相应新闻。
