# 翡翠休息室 · 大提琴音乐角交付说明

本次只在现有 Lord Chryser 翡翠休息室增加独立音乐角。原始背景、椅子、地毯、家具、八个机关及原有游戏入口均保留。新增模块出错时有自己的恢复界面，不会替换整个房间。

## 美术与摆放

- 使用现有 `public/chryser-private-lounge.png` 作为透视、材质和光照参考，通过内置图像生成制作独立、真实透明通道的大提琴陈设；原背景没有被重绘。
- `public/cello/cello-corner.webp`：1024 × 1536，约 312 KiB。深琥珀木色传统四弦大提琴、古典弧形胡桃木架、少量黄铜、专用琴弓位置与小型乐谱架一体制作，带局部接触阴影；转换 WebP 保留 alpha。
- 放在原椅子前左侧的地毯上。位置、尺寸、旋转、琴身/乐谱命中区、四根弦的局部坐标集中在 `scene-config.ts`，按房间图层百分比定位，未硬编码到屏幕像素。
- 场景默认无标签、发光、持续跳动或描边。仅键盘 focus 可见细线，透明命中区之外的点击穿透到原机关。
- 这是高质量独立栅格图层与局部动画，不是可自由绕行的 3D 乐器模型。

## 三项交互

| 交互 | 当前实现 |
| --- | --- |
| 四弦试奏 | 琴身点击进入平滑特写；琴弦位置、四个按钮及键盘 1–4 可奏 C2/G2/D3/A3；真实大提琴拨弦采样、细微弦振动、连续点击、音量/静音、止弦、Esc/关闭返回。离开或隐藏页面时停止声音，关闭时销毁音频上下文。 |
| 私人乐谱 | 古典纸张与五线谱、书签、翻页、上下份乐谱；标题、作曲家、正文、私人备注；真实上传 PNG/JPEG/WebP 乐谱图片和 MP3/WAV/OGG/M4A 录音；图片翻页及录音播放；增订和删除；并发版本保护。 |
| 访客旋律 | C3–C4 完整一个八度的八个自然音，最多 32 个音符；½/1/2 拍、休止、速度、选中修改、删除、重来、试听；结构化保存、真实会话身份、服务器时间、留言卡、重新播放、历史分页、本人/主人整理。提交重试不会重复创建同一旋律。 |

这里的琴音是具有真实大提琴音色的 **pizzicato 拨弦**；没有声称已经实现持弓、连续运弓、揉弦或力度演奏。采样来源、原始文件映射、转换方法和许可在 `public/cello/audio/SOURCES.md`。四个音频合计约 146 KiB，按需解码，不自动播放。

乐谱与旋律入口均复用原登录，未新建登录页。减少动画遵循系统设置，也可在音乐角内切换；进入/退出动画可被后续统一的 `window.dispatchEvent(new Event('schicksal:skip-animation'))` 提前结束，交互结果与保存请求独立于动画。进入动画期间再次轻触也会完成动画。

## 身份、数据与文件

| 内容 | 保存位置与权限 |
| --- | --- |
| 乐谱文字、私人备注、版本 | 原 Cloudflare D1 的 `emerald_music_scores`；私人备注在服务器对未授权浏览者剔除。 |
| 乐谱图片、录音元数据 | D1 `emerald_music_assets`；实际文件复用服务端 `getPhotoStorage`，存入现有 Supabase 私密桶的 `cello/zxy/<score-id>/<asset-id>` 前缀。没有公开文件 URL 或前端存储密钥。 |
| 音乐留言 | D1 `emerald_music_melodies`，音符 JSON、节拍、速度、站内身份、服务器 ISO 时间；界面显示完整 UTC+8 年月日时分秒。 |
| 授权 | D1 `emerald_music_editors`。zxy（本室主人）和 amberina（站点主人）默认管理；truth 默认只读乐谱、可创作自己的音乐留言。两位主人可明确授予或撤销 truth 的乐谱编辑、私人备注阅读及留言管理权。未自动给其他成员权限。 |
| 未提交草稿 | 仅旋律草稿保存在以成员 ID 分隔的本机 localStorage，界面明确显示未提交。服务器确认成功后才显示“已收进留言册”。草稿不等于跨设备保存。 |

新增迁移 `0010_emerald_cello_music.sql` 由现有 Cloudflare 部署脚本在部署前应用。未增加第三方服务或付费资源，原 Free 部署路线未改变。

API 使用 `currentMember(request)` 验证真实 session；提交还校验同源与当前客户端成员，忽略客户端伪造作者/创建时间。图片/音频按文件头检查格式，流式限制请求大小，图片单页 4 MB、每份最多六页，录音单份 8 MB、每份一条，最多 100 份乐谱。媒体经过登录后代理，支持私密缓存和音频 Range 请求。

乐谱/附件更新有 revision 冲突保护。附件数据库更新使用事务批次与 write token，避免并发上传串入另一版乐谱。删除先使记录和媒体不可访问，再清理存储文件；若清理服务暂时失败，保留不可访问的墓碑，下一次媒体变更时重试。若上传完成后数据库和清理均失联，可能留下未被引用的私密对象，后续可以加定期孤立文件整理；不会返回公开访问地址。

## 实际验证

- 新模块自动化：23 项通过，覆盖四弦映射、节奏、32 音符完整播放调度、静音、按需加载/缓存、失败重试、关闭后阻止迟到播放、真实 session 与越权、私人备注剔除、同源限制、版本冲突、上传/私密读取/Range、附件上限、授权撤销、音乐留言幂等、历史分页、删除、数据库关闭后重新打开及跨成员读取。
- 原功能回归：Lounge 聊天历史 5 项、全站私密访问 12 项、原小游戏引擎 14 项通过；相关测试总计 54 项通过。
- 音乐角客户端独立 TypeScript 检查通过；Vinext 生产构建通过。整个仓库的 `tsc --noEmit` 仍受原有缺失 `cloudflare:workers` 类型及旧小游戏 readonly 测试类型问题影响，不能报告为全仓类型检查通过。现有 `test:photos` 指向的测试文件在当前恢复的检出中缺失，未把它计为通过。
- 实际浏览器运行：桌面场景位置和特写、四弦点击、空弦练习、旋律输入/试听/提交/重播、乐谱新增、两页图片上传与翻页、MP3 上传和实际播放、退出返回、键盘 Esc；原壁炉、座钟、雨窗、扶手椅和札记仍能操作。
- 390 × 844 窄屏 iframe 验收：四弦触控尺寸、手稿与创作布局、无横向溢出、旋律播放；切换本机测试成员后能读到同一段旋律，访客看不到私人备注或编辑控件。
- 浏览器验收运行真实路由与本机持久 SQLite/私密文件目录，没有模拟保存成功。生产代码使用原 D1 和 Supabase。未在生产账户上传测试记录，未代主人创建演奏或私藏。

尚未完成的实机验证：iPhone/Safari 和实体触摸屏、耳机/扬声器听感、低性能设备持续使用，以及生产环境两台真实设备分别登录后的操作。自动化和本机浏览器通过不能代替这些实机验收。上传的录音仍需浏览器支持其编解码；读取/解码失败会明确提示。

## 示例与素材边界

正式初始界面只有明确标注的原创“四根空弦练习页”，可以播放。主人的乐谱、私人批注和演奏录音需要本人上传。开发浏览器中的原创测试谱页、测试录音和留言只在本机验收环境，不写入生产数据库。没有引入未经授权的第三方曲谱或表演录音。

本次不实现录音采集、专业作曲排版、MIDI 导入导出、PDF 阅读、实时合奏、弓压/揉弦。后续可在当前结构化音符与私密附件机制上增添，不需改造整间休息室。
