## What is implemented

- Book inquiry in the central emblem dialog: keyword/semantic mode, deliberate submit, optional source-based answers, book title -> contents; chapter -> original reader/anchor, single click/double click retains existing selection controller. Full-collection button opens a distinct React search surface, with current book / Gallery / digital results and protected exact-version reader. Original collections/favorites stay intact. Existing native search when feature off remains unchanged.
- Live corpus: current published book revision, authored block text, generic Unicode word segmentation + Han bigrams, bounded chunks with overlap, BM25-style ranking; current ready Gallery and digital metadata, not drafts/trash/pending versions. Contents and metadata are rebuilt from live authoritative records each request. No prior-book-specific dictionaries. Index stores content-addressed normalized vectors only, never treats an index as authority for visibility or content. Cache namespace includes provider/model/version. Ranking fuses lexical and vector ranks using RRF, optional reranker, returns up to 30 results. Exact book-title TOC preserved. No silent old-text fallback. Recheck current membership/source ACL and live hit keys after inference. Search does not record raw user questions.
- Provider ports: native Workers AI `SEARCH_AI` binding for `@cf/baai/bge-m3`, or private service binding `SEARCH_EMBEDDINGS` with `/v1/embeddings`, compatible request `{model,input:string[]}`, response `{data:[{index,embedding:number[]}]}`. `SEARCH_RERANK` optional `/v1/rerank` request `{model,query,documents}`, returns `{results:[{index}]}` in ranked order, full permutation. `SEARCH_GENERATION` optional `/v1/grounded-answer` request `{model,query,evidence:[{id,text}],instruction}`, response `{answer,citations:number[]}`. The generation service must isolate instructions from untrusted evidence; citation ID validation is NOT proof of factual entailment. Outputs are text only, not HTML. No tool actions, external links, or agent privileges granted to model. Real provider calls not executed in development environment; tests use injected binding fixtures. Native BGE-M3 example follows https://developers.cloudflare.com/workers-ai/models/bge-m3/ (model schema and actual inference must be verified in dedicated preview; docs have differing example/schema forms). Other providers require an actual configured compatible service. No external model/data transmission occurred in this work.
- Index lifecycle: missing content fingerprints identified automatically, each manual or scheduled run processes up to 16 unique texts, unchanged chunks reuse vectors, new versions appear immediately in lexical search, semantic readiness reflects indexing progress. Old cache entries are inert but retained; no deletion. Worker scheduled handler provided, requires explicit preview-only cron configuration. No running cron installed. Daily UTC atomic reservation caps (input items, not tokens or dollars); denied provider/failure does not fabricate semantic success. Native inference timeouts and actual resource limits need production-like testing.
- Ministry: search index status/coverage/model readiness, manual batch, daily budget counters, last 20 runs; editable open/paused, semantic model permission, AI answer permission, auto-index permission, daily input limits within deployment ceiling. Revision CAS and exact incumbent term/elevated session checked in one SQL statement. Append-only audit/history restore as new revision. Existing V2.0 profile/permissions/account pages retained. Search ACL reads the same Ministry policy table; per-source read permissions govern POST search (no content mutation), existing module ACL remains ceiling; source-specific detail route requires fresh authorization. Books conservatively require library + archives access.

## Important limitations / acceptance

- This is a small-corpus first backend, NOT a deployed vector database: hard limits 120 current books, 8 MiB serialized book payloads, 1200 passages and 800k source characters, 30 results, 400-character query. Capacity overflow is explicit error, not partial silent truncation. Future large library requires external vector/FTS backend, indexing pagination and calibrated relevance threshold. Current fixed cosine floor 0.38 is a starting heuristic, not relevance validation.
- Full collection search covers current published book text and current ready image/digital titles, collections, filenames, Gallery tags. It does NOT currently embed pixels, audio, video, model geometry, PDF body, ZIP contents, or old Gallery/digital versions; exact old version can be read by existing permitted version detail, but historic-version search is not implemented. This engine accepts arbitrary chapter IDs/text, while the previous library publisher still enforces seven AVS chapter IDs. Removing that legacy publishing constraint and replacing content is a separate change; no existing text was modified.
- New semantic UI default false; default server gate disabled. Real framework build, TypeScript React full type check, Chromium/WebKit behavior, touch, real Workers AI contract/quality, real D1 query/memory/latency limits, Cloudflare usage/price, and cron execution remain unverified. No automatic model enablement or external API billing. Before activation, approve what content may be sent to model service, bind preview DB and isolated service, verify rate/cost caps, test authorization and model privacy. Model text is limited to eligible published sources, but index admin can process all enabled shared collections. No passive search logging.
- Search settings and index runs are additional tables; update prior offline backup allowlist and verify restore before production. Embeddings are derivable and may be rebuilt; settings history is not derivable.
- No major changes to other Ministry modules in this increment; only search-control management added. Existing separate packages remain required.
