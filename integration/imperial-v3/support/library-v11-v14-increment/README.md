# Schicksal Library — cumulative V1.1–V1.4 Smart Collection extension (round 16)
2026-11-27. Cumulative replacement for the Preview Sync increment, not R4 or the original art handoff. Frozen accepted V1.0 R4: `e5452b4517435c25004d15299d060c8f149ed0c8`. No remote writes, deployment, storage activation or production database changes.

## New convenience and autonomy features
1. **Unified discovery**: `/api/library/discovery?kind=all&q=...` queries enabled book, Gallery and digital sources in one request (up to eight results per category, explicit disabled-source status). Each source supports independent bounded pagination; book title/author/chapter title/note/Markdown; Gallery title/collection/tag/current filename; digital title/collection/current filename. Only current published books and non-trashed ready originals are searched. Fixed published historical book versions and original asset version IDs can be opened explicitly. SQL substring matching, not semantic search, OCR, or full-text indexing; no claim of production-scale performance. Candidate UI directly opens plain Markdown chapter/book, safe image derivative or digital preview/download. Does not replace R4's crest and animation reader.
2. **Personal collection and notes**: `/api/library/workspace` uses actual authenticated actor, no caller-selected identity. Manual save of a fixed version or chapter, remove own save, optional 1,000-character note with optimistic revision guard; 300 saves per member, idempotent retry, private JSON export. No passive reading history, analytics or auto-tracking; bookmarks are explicit. Existing shared library backup deliberately excludes private bookmarks/notes; the owner can export their own. Import of personal bookmarks is not implemented. A saved target can become unavailable (trash or disabled module); it is not silently replaced by a newer version, and the member can remove their own save.
3. **Gallery historical comparison**: select two immutable versions across history pages, side-by-side / wipe / opacity blend, swap A/B, zoom/reset, individually download originals, note exact original SHA equality. Uses authenticated safe preview/thumbnail derivatives, not arbitrary uploaded bytes. No automatic image registration, similarity assessment, or color-management guarantee. Candidate UI only, not browser-tested or art-approved.
4. **Portable Gallery upload queue**: export pending jobs into a private JSON manifest scoped to the exact preview origin + SHA + elevated minister ID; no credentials or file bytes. Reselect originals in any order and match size/name/SHA; recover stable request IDs and expected version base. After replay, query existing authenticated derivative and skip if available; missing derivative only is uploaded. Existing pending queue is not silently overwritten. User must export before leaving; no automatic browser persistence. Direct small digital uploads are still not recovered across sessions except via the earlier local watcher. No production or live transfer test.
5. **Automatic large-file fingerprint**: bounded-memory incremental SHA-256, reads 1 MiB at a time and yields between blocks. Digital panel computes expected hash automatically (optional independently supplied check), with progress/cancel. Resume verifies full file before contacting server, even completed task replays; server still verifies every part and whole digest. Standard vectors, boundary sizes, cancellation and generated 86 MiB fixture match Node native SHA. New uploads may compute the whole digest twice (creation and resume preflight); browser responsiveness on real mobile devices still needs measurement. Not a new cryptographic security mechanism; authoritative server checks unchanged.
6. **Local batch preflight**: `tools/plan-collection-batch.py` groups a user-selected folder by first subfolder and namespace, suggests title/version based on filename, reports same-namespace exact SHA duplicate candidates, sizes and skipped files. Does not merge works, upload, delete, or modify anything. `tools/watch-collections.py --group-by-folder` is explicit opt-in; same first-directory mapping, root files use --collection, state binds to exact policy and preview. Previous state without this option still supported; changing policy requires a distinct state file and manual review to avoid duplicated imports. Simulated transport only.
7. **Asset reference reconciliation**: `tools/plan-asset-links.py` consumes an immutable Git scan and an explicit local SQLite snapshot; exact original-byte SHA matches only; unique active version becomes a proposed link with deterministic ID; multiple matches, trashed-only, unregistered and already-linked cases separated. Does not register, revoke or delete. Rejects directory snapshot reports for proposed links. Static scanner limitations remain; every candidate must be manually reviewed against actual code.
8. **Technology Ministry health dashboard**: `/api/library/health` checks ten metadata counts (drafts, pending blobs, missing thumbnails, open/old tasks, works without versions, broken active references). Server requires current elevated minister and governance preview flag. Read-only; no automatic cleanup, fixes, or claim of physical bucket integrity. Candidate UI available under asset governance.
