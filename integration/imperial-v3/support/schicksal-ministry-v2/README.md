# Schicksal · Ministry of Technology V2.0 Alpha

**独立预览候选，不是生产版。** 基于站长确认的最高技术管理、成员信息与权限调控定位。本包独立于 R4 和 Smart Collection；不替代任何此前的馆藏交付。

## 已实现
- 科技部新控制中心：实测数据概览（当前版本标识、有效期内会话计数、八席、配置版本）、档案、权限矩阵、运行调控、账号安全、审计历史。旧照片入口、R4 图书馆调试入口与密码管理保留在账号安全。
- 八席档案补录/修改：显示名称、英文名称、代号、档案称号（不构成公职任命）、公开简介。普通成员只能读取五个已有登录身份的公开补充档案；封存席位资料只在部长后台。侧边栏成员显示及个人/公开档案补充区提供候选联动。尚未把登录页、名册、议会、卡牌、图谱、固定艺术素材的身份文字改为动态数据源。空字段沿用原资料；原标识色及八棱顺序完全不改。
- 账号冻结及解冻：仅五个现有登录身份；禁止冻结现任部长；冻结时同一 SQLite 触发器撤销现有会话，禁止冻结期间新建会话；修改原认证入口使冻结期间不能登录。解冻不恢复原有会话。冻结的成员能否被任命为新部长仍须在原政治任职流程增加资格校验；不应在验收前启用生产冻结。
- 统一功能注册表：家庭影像馆、国家档案馆、图书馆、Gallery、数字藏品。逐人设置沿用、禁止、只读、允许使用（沿用原权限上限），整体设置开放、只读、暂停。已接入候选 Worker 前置请求检查及主站对应页面读取权限提示，所有既有模块服务端检查继续生效。不是无条件授权；不能靠此模块突破委员会资格、身份、资源所有权、隐私或未部署模块。请求方法作为第一层读写划分；仍须审计 GET 副作用与所有实际别名/资源路径。
- 跨馆藏公共检索、收藏接口采取保守交集限制；任何相关域受限时可能连带阻止共享接口，包括动态国家档案馆和私人收藏。这是第一版的已知粗粒度限制，未来应进行域级过滤，避免不必要地拒绝访问。
- 每次更改需要理由、对象当前版本、部长当前任期；单条条件 INSERT 核验有效部长会话、当前唯一任职者、任期及版本，避免并发覆盖。历史只追加、不可原地更新删除；恢复产生新版本。既有密码/照片管理仍用原服务与日志，不宣称已统一审计。
- 诊断只解释本层规则，不声称模拟整个原模块身份权限。
- 只在 `SCHICKSAL_MINISTRY_V2=1` 且 `SCHICKSAL_PREVIEW_COMMIT` 为完整 SHA 的环境启用。默认关闭，迁移独立保留。该开关不等于云端部署隔离，必须人工确认专用 Worker/D1 后才启用。未启动任何云资源。

## 安装前检查
`python3 apply-ministry-local.py /path/to/repo --check`：严格要求干净的 `e31fe637aeb629bb0a2cf42223041f2c0755871a`（main）或 `e5452b4517435c25004d15299d060c8f149ed0c8`（已验收 R4）。验证 5 个源文件 blob SHA、替换锚点及新增路径无冲突。仅验证不写文件。去掉 --check 后创建本地独立分支并复制 overlay、应用五处修改，不提交/推送/迁移/部署。若先接入 Smart Collection 或基线更新，需人工重审重叠路径（尤其科技部/页面入口），不能强制覆盖。

`proposals/ministry-v2.sql` 是 SQL 提案，不分配主站迁移编号。**只用于专用预览 D1**，先执行原主站迁移，验证现任部长表和会话表。不要写生产数据库。关闭开关后将恢复旧版权限/资料来源，冻结约束触发器仍存在于已迁移数据库；不能把关闭开关当作回滚方案，须单独设计迁移回滚和权限状态恢复。

